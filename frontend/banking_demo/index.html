● SecureBank Identity Verification

Bienvenue dans SecureBank Identity Verification

Cette démonstration simule un parcours bancaire sécurisé pour vérifier l'identité d'un utilisateur à partir d'une vidéo capturée en temps réel.

Challenge actif

Un challenge est généré automatiquement afin de limiter les attaques par photo, vidéo rejouée ou tentative de réutilisation.

Détection de vivacité

Le système vérifie que l'utilisateur réalise bien l'action demandée : clignement, sourire ou mouvement de tête.

Modèle PAD FOMA V6

Le modèle analyse la vidéo avec une approche multimodale : CNN-LSTM, rPPG, comportement et posture.

Décision bancaire

La réponse finale est adaptée au contexte bancaire : ACCEPT, RETRY ou REJECT.

Politique de sécurité

ACCEPT

Identité vérifiée et accès autorisé.

RETRY

Nouvelle capture demandée si le score ou la qualité est ambiguë.

REJECT

Risque d'attaque détecté ou non-respect du challenge.

La caméra sera activée uniquement après le démarrage de la vérification.

● Paramètres sécurité avancés

          
Paramètres de sécurité bancaire

          

            Cette page regroupe les règles appliquées dans le prototype PAD FOMA V6 : décision métier, tentatives, challenge actif, journalisation et limites de production.
          

        

        

          
          
        

      


      

        

          

            

              
⚖

              
Politique de décision

              
Le système applique une logique métier bancaire : ACCEPT pour autoriser, RETRY pour demander une nouvelle capture, REJECT en cas de risque d’attaque.

            

            

              
↻

              
Gestion des tentatives

              
Après 3 tentatives RETRY non concluantes, une pause de 120 secondes est appliquée pour limiter les répétitions abusives.

            

            

              
ID

              
Challenge à usage unique

              
Chaque vérification crée un challenge temporaire. Après analyse, il est marqué comme utilisé pour éviter toute réutilisation.

            

            

              
▤

              
Traçabilité

              
Les décisions, résultats JSON, vidéos uploadées et messages système sont conservés pour faciliter l’audit technique de la démonstration.

            

          

        


        

          

            

              
Règles de décision

              
Traduction métier des sorties du modèle PAD et du module de vivacité.

            

            ACCEPT / RETRY / REJECT
          

          

            
            ACCEPT
            
L’identité est vérifiée : liveness validé, score PAD faible et qualité vidéo suffisante.

          

          

            
            RETRY
            
Nouvelle capture demandée si la vivacité échoue, si la qualité est moyenne ou si le score PAD est ambigu.

          

          

            
            REJECT
            
Vérification refusée lorsqu’un risque d’attaque de présentation est détecté.

● Modèle actif
FOMA V6 — Détails du modèle
Prototype PAD bancaire multimodal pour la détection d'attaques de présentation faciale.

        
      

      

        
ModèleFOMA V6

        
Type de systèmePAD vidéo bancaire

        
ArchitectureMobileNetV3 + LSTM + fusion comportementale

        
Mode runtimeChallenge actif + liveness + modèle PAD V6

        
FeaturesEAR, blink_count, motion, rPPG, head pose

        
Fusion0.85 score multimodal + 0.15 behavior-pose

        
Sortie métierACCEPT / RETRY / REJECT

        
DatasetsCASIA-FASD + AxonLabs + MSU + données locales

        
ObjectifDétecter les attaques de présentation faciale dans un contexte bancaire.
